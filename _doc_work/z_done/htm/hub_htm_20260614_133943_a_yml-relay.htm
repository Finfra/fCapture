세 가지를 처리했습니다. ① relay 지연 옵션을 CLI 플래그뿐 아니라 설정 파일(JSON·companion YAML)에서도 지정할 수 있게 확장, ② t4.default_jm4.yml(실제 파일 ~/.fCapture/jm4/t4.default.yml)에 relay: 3 적용, ③ 실제 캡처 스크린샷 생성. 더불어 companion YAML 구조를 _doc_arch/ 영속 설계 문서로 정리했습니다.

① yml/config 기반 relay 지원

Issue20에서 --relay N 은 CLI 플래그로만 동작했습니다. 이제 설정 파일에 값을 넣어두면 그 값으로 지연합니다. 우선순위는 CLI --relay > 설정 파일 relay 입니다.

변경 지점내용
ScreenCaptureConfigrelay: Double? 필드 + CodingKey 추가 (JSON 디코딩 대상)
resolveRawConfigReferencesrelay 의 {경로} companion 참조 해석 추가 — YAML 문자열을 Double 로 치환
main()지연값 = overrides.relay ?? config.relay (CLI 우선)

② t4.default_jm4.yml 적용

YAML 값 저장소에 relay: 3 을 추가하고, 이를 참조하도록 jm4_Screen.json 에 relay 참조 한 줄을 더했습니다.

# ~/.fCapture/jm4/t4.default.yml (말미에 추가)
relay: 3   # 캡처 N초 지연 후 실행

# ~/.fCapture/jm4/jm4_Screen.json (필드 추가)
"relay": "{~/.fCapture/jm4/t4.default.yml}"
두 파일은 repo 밖 사용자 설정(~/.fCapture)이라 git 커밋 대상이 아닙니다. 코드와 설계 문서만 커밋했습니다.
