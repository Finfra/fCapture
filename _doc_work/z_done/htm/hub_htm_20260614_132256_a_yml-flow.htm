fCapture — t4.default_jm4.yml 동작 흐름

📁 fCapture 🆚 세션 🎯📊

핵심 결론

이 YAML 파일은 fCapture에 직접 인자로 줄 수 없습니다. fCapture t4.default_jm4.yml 로 실행하면 JSON text did not start with array or object 오류로 실패합니다(실측 확인). fCapture의 설정 로더(loadConfig)는 오직 JSON만 파싱하기 때문입니다.

YAML은 companion 참조 메커니즘을 통해서만 동작합니다. 즉 JSON 설정 파일이 그 안에서 {경로} 패턴으로 YAML을 참조하고, fCapture가 디코딩 직전에 그 참조를 YAML 값으로 치환합니다.

파일 관계

IDE에서 연 ~/_doc/1.Area/_memo/t4.default_jm4.yml 은 사실 심볼릭 링크이며, 실제 파일은 ~/.fCapture/jm4/t4.default.yml 입니다. 이 YAML 한 개가 jm4 머신의 캡처 설정 값(SSOT)을 보유하고, 여러 JSON 래퍼(Screen / Window / Region / Scroll)가 모두 같은 YAML을 참조합니다.

파일역할
_memo/t4.default_jm4.yml편집 편의용 심볼릭 링크 → 아래 실제 파일
~/.fCapture/jm4/t4.default.yml실제 값 저장소 (capturePath, target, fileFormat, flash, shadow 등)
~/.fCapture/jm4/jm4_Screen.json화면 캡처 진입 JSON — 모든 필드를 {...t4.default.yml} 로 참조
jm4_Window / Region / Scroll.json같은 YAML 참조, target 종류만 다른 래퍼

실제 YAML 내용

capturePath: 0
capturePathArray:
  - "~/Desktop"
  - "~/Desktop/tmp"
  - "/Users/nowage/GoogleDrive_finfra/2026x"
target:
  name: "screen"
  number: 1
fileFormat: "%d_%T_%target"
"window_flash": true
"shadow": false

이 YAML을 참조하는 JSON (jm4_Screen.json)

{
    "target": "screen:{~/.fCapture/jm4/t4.default.yml}",
    "capturePath": "{~/.fCapture/jm4/t4.default.yml}",
    "capturePathArray": "{~/.fCapture/jm4/t4.default.yml}",
    "fileFormat": "{~/.fCapture/jm4/t4.default.yml}",
    "window_flash": "{~/.fCapture/jm4/t4.default.yml}",
    "shadow": "{~/.fCapture/jm4/t4.default.yml}"
}

전체 동작 흐름

올바른 실행 명령은 JSON을 인자로 주는 것입니다 (예: fCapture ~/.fCapture/jm4/jm4_Screen.json).

flowchart TD A["fCapture ~/.fCapture/jm4/jm4_Screen.json"] --> B["parseArguments()
비옵션 인자 → configFile 판정"] B --> C["loadConfig(path)
JSONSerialization 으로 JSON → dict"] C --> D["resolveRawConfigReferences(&dict)
각 필드의 {경로} 패턴 탐지"] D --> E["findCompanionYAML()
참조 경로의 실제 yml 파일 해석"] E --> F["parseSimpleYAML / parseYAMLArrays
해당 필드 값 추출"] F --> G["dict 값 치환
screen:{ref}→screen:1, capturePath→0,
array→경로목록, flash→true ..."] G --> H["치환된 dict → JSON → JSONDecoder
→ ScreenCaptureConfig"] H --> I["capturePath=0 → capturePathArray[0]
= ~/Desktop 저장 경로 확정"] I --> J["mergeConfig(CLI 오버라이드 적용)
예: --relay, -p, -t ..."] J --> K["performCapture(config)
screen:1 캡처 → ~/Desktop 저장"]

필드별 치환 결과

JSON 원본YAML 참조 값최종 치환
"screen:{...yml}"target.name=screen, number=1"screen:1" (number=-1이면 all)
capturePath "{...yml}"capturePath: 00 (Int → 배열 인덱스)
capturePathArray "{...yml}"리스트 3개["~/Desktop", …]
fileFormat "{...yml}""%d_%T_%target"그대로
window_flash "{...yml}"truetrue (Bool)
shadow "{...yml}"falsefalse (Bool)

capturePath: 0 은 capturePathArray 의 인덱스 0(= ~/Desktop)을 가리킵니다. 인덱스를 1로 바꾸면 ~/Desktop/tmp, 2면 GoogleDrive 경로로 저장됩니다.

companion 파일명 탐색 규칙

findCompanionYAML 은 참조 경로가 존재하지 않을 때 형제 파일을 자동 탐색합니다. 우선순위는 {baseName}.default.yaml → {baseName}.yaml → {baseName}.yml, 그다음 첫 컴포넌트만 사용한 {firstPart}.default.yaml … 순입니다. 덕분에 t4.basePath.txt 같은 placeholder가 t4.default.yml 로 자동 연결될 수 있습니다.

요약

  • YAML은 값의 단일 출처(SSOT) — 직접 실행 대상이 아님
  • 실행은 JSON 래퍼로: fCapture ~/.fCapture/jm4/jm4_Screen.json
  • JSON 내부 {경로} → 디코딩 직전 YAML 값으로 치환 (resolveRawConfigReferences)
  • 같은 YAML을 Screen/Window/Region/Scroll JSON이 공유, target 종류만 다름
