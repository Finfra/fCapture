yaml-companion-config.md — 2건

findCompanionYAML 의 탐색 순서 서술이 실제 루프 구조와 달랐습니다. 문서는 "baseName 후보 3종을 전부 훑은 뒤 firstPart 로 넘어간다"고 적었지만, 코드는 확장자가 바깥 루프라 확장자 하나마다 baseName → firstPart 를 교대로 확인합니다.

순서실제 후보 (t4.basePath.txt 참조 시)
1t4.basePath.default.yaml
2t4.default.yaml
3t4.basePath.yaml
4t4.yaml
5t4.basePath.yml
6t4.yml

그리고 이 표를 만들면서 두 번째 문제가 드러났습니다. 문서는 "덕분에 t4.basePath.txt placeholder 가 t4.default.yml 로 자동 연결될 수 있다"고 주장했지만, 후보 목록에 t4.default.yml 이 없습니다. 확장자 배열이 ["default.yaml", "yaml", "yml"] 이라 .default 접미는 .yaml 하고만 결합하기 때문입니다. 정작 실제 운영 파일과 번들 템플릿은 모두 .yml 입니다.

진입 가드 2건(참조 경로가 이미 yaml/yml 이면 탐색 생략, 파일이 실존하면 탐색 생략)도 문서에 없어 함께 보강했습니다.

Glossary.md — 2건

즉 JSON 설정에 "target": "region" 을 적으면 인터랙티브 영역 선택이 되지 않습니다. 표를 두 경로로 분리하고 이 함정을 경고로 명시했습니다.

나머지 한 건은 "버전 출력 (현재 1.0.18)" 하드코딩입니다. 릴리즈마다 낡아지는 값이므로 VERSION 파일 참조 표현으로 치환해 같은 종류의 stale 이 재발하지 않게 했습니다.

정합 확인 12건

대조 결과 문제가 없던 항목입니다. 참조 경로 12종과 인용 심볼 13종이 전부 실존했고, 인용된 라인 번호 5곳(appVersion:420, Bundle.main 4곳)도 정확했습니다.

다만 라인 번호 인용은 코드가 조금만 바뀌어도 밀리는 취약한 형태이므로, 정확했음에도 심볼명 기준으로 전환했습니다. 예를 들어 ScreenCaptureApp.swift:858,887,922,960 대신 createBundleYAMLIfNeeded·loadOrCreateDefaultSetting·createBundleFileIfNeeded·printHelp 로 적었습니다.

이 전환 과정에서 제가 함수명 하나를 추측으로 적을 뻔했습니다(createBundleSettingIfNeeded). 즉시 grep 으로 확인해 실제 이름(loadOrCreateDefaultSetting)으로 고쳤습니다 — stale 을 고치는 작업이 새 stale 을 만들면 의미가 없기 때문입니다.
