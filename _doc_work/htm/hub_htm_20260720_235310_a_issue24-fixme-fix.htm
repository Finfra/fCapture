수정한 결함

1. companion YAML 확장자 목록 누락 해소

findCompanionYAML 의 확장자 배열이 ["default.yaml", "yaml", "yml"] 이었습니다. .default 접미가 .yaml 하고만 결합하는 구조인데, 정작 실제 운영 파일과 번들 템플릿은 모두 .yml 이라 .default.yml 을 노린 fallback 이 통째로 무동작이었습니다.

for ext in ["default.yaml", "default.yml", "yaml", "yml"] {

탐색 후보가 6종에서 8종으로 늘었습니다.

2. printHelp 의 flash 기본값 오기 해소

fallback 도움말이 --no-flash 를 기본값이라고 표기했는데, 실제 기본은 flash ON 입니다(config.windowFlash ?? true). 번들 Usage.txt 쪽 표기가 맞았으므로 그쪽에 맞춰 정정했습니다.

3·4. -r 프리셋과 --region 좌표 옵션 혼동 해소

번들 Usage.txt 가 -r, --region 을 한 프리셋으로 병기하고 있었으나, --region 은 좌표를 받는 별개 옵션(--region x,y,w,h)입니다. parseArguments 에서 프리셋으로 인식되는 것은 -r 단독뿐이라, 프리셋 분기의 case "-r", "--region": 중 "--region" 은 도달할 수 없는 dead branch 였습니다.

Usage.txt 는 -r 단독 + 괄호 주석으로 정정하고, 분기는 case "-r": 로 좁히면서 왜 --region 이 여기 오지 않는지를 주석으로 남겼습니다.

부수 발견 — -r 항목 자체가 도움말에 없었음 추가 처리

수정 후 --help 출력을 확인하다가 알게 된 것인데, printHelp fallback 의 프리셋 목록에는 -s·-w·-f 만 있고 -r 이 아예 빠져 있었습니다. 문서 감사에서도 잡히지 않은 항목이라 함께 추가했습니다.

프리셋 플래그:
  -v, --version             버전 출력
  -h, --help                도움말 출력
  -s, --screen              스크린 전체 캡처 (defaultScreen.json 사용)
  -w, --window              윈도우 캡처 (defaultWindow.json 사용)
  -r                        영역 캡처 (defaultRegion.json 사용, --region 은 좌표 옵션)
  -f, --fixRegion           마지막 영역 좌표 고정

검증

표기 수정 3건은 release 빌드 후 --help 실제 출력으로 확인했습니다. 문제는 1번 companion fallback 이었습니다 — 이건 출력만 봐서는 동작 여부를 알 수 없어 실제로 돌려야 했습니다.

임시 fixture 로 capturePath 가 존재하지 않는 t4.basePath.txt 를 참조하는 설정과, 형제 위치의 t4.default.yml 을 만들어 실행했습니다.

[INFO] t4.basePath.txt 미존재 → companion t4.default.yml 사용
[INFO] 스크린샷이 저장되었습니다: /tmp/ctout/20260720_234811.png

fallback 이 걸린 로그뿐 아니라 yml 안의 capturePath 값이 실제 저장 경로에까지 반영된 것을 확인했습니다.

첫 시도는 실패했습니다. yml 에 키를 basePath 로 적었는데, companion 이 읽는 필드명은 placeholder 파일명이 아니라 JSON 쪽 키(capturePath)입니다. fallback 로그는 떴지만 저장 경로가 Desktop 으로 떨어져서 알아챘습니다. 로그만 보고 통과로 판정했으면 절반만 검증한 셈이 됐을 것입니다.

테스트로 생성된 스크린샷 3장(Desktop 2장, /tmp 1장)은 실행 직후 제거했습니다. 상태 파일의 ID 카운터는 3까지 올라갔습니다.
