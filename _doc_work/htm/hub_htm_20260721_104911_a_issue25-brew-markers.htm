[1] Bundle 리소스 접근 — 안전 헬퍼 도입 해소

증상은 명확했습니다. Package.swift 가 프리셋 JSON·YAML·Usage.txt 를 .copy() 리소스로 선언하고 있어 SPM 은 이들을 별도 fCapture_fCapture.bundle 로 패키징하는데, 코드는 Bundle.main 으로 접근하고 있었습니다. Bundle.main 은 실행 파일 위치를 메인 번들로 잡을 뿐 옆의 .bundle 안을 보지 않으므로, 리소스를 전부 놓쳤습니다. 실제로 앞선 --help 출력이 번들 Usage.txt 가 아니라 하드코딩 fallback 이었던 것이 그 증거였습니다.

왜 Bundle.module 단순 치환이 아니었나 crash 리스크

문서의 FIXME 는 "정석은 Bundle.module 로 전환"이라고 적혀 있었지만, 그대로 하면 오히려 배포본을 깨뜨립니다. SPM 이 생성하는 Bundle.module accessor 는 리소스 번들을 찾지 못하면 fatalError 를 냅니다.

brew 배포본은 tarball 에 바이너리 하나만 넣습니다(번들 미포함). 그 상태로 Bundle.module 을 처음 접근하는 순간 — 예를 들어 새 사용자가 처음 실행해 ~/.fCapture/ 템플릿을 만들려는 시점 — 즉시 crash 합니다. FIXME 를 곧이곧대로 따랐다면 brew 사용자 전원이 첫 실행에서 죽는 회귀가 됐을 것입니다.

그래서 Bundle.module 을 직접 쓰지 않고, crash 없이 nil 을 반환하는 헬퍼를 만들어 4곳에서 호출하게 했습니다.

private static func bundledResourceURL(_ name: String, withExtension ext: String) -> URL? {
    if let u = Bundle.main.url(forResource: name, withExtension: ext) { return u }
    let sibling = Bundle.main.bundleURL.appendingPathComponent("fCapture_fCapture.bundle")
    if let b = Bundle(url: sibling), let u = b.url(forResource: name, withExtension: ext) {
        return u
    }
    return nil
}

치환된 소비부는 createBundleYAMLIfNeeded·loadOrCreateDefaultSetting·createBundleFileIfNeeded·printHelp 4곳입니다. 모두 nil 을 이미 graceful 하게 처리하고 있어 배포본은 그대로 안전합니다.

[2] 릴리즈 자동화 — deploy-brew.sh 신규

문서의 🚧 TODO 는 릴리즈 절차를 bin/deploy-brew.sh 로 자동화하라는 것이었습니다. 그런데 참조하라던 version-manager-m 의 fsc-deploy-brew.sh 패턴은 실물이 없었고, bin/ 은 .gitignore 대상이라 그 경로에 두면 커밋되지 않습니다. 그래서 buildAndTest.sh 와 나란히 루트에 deploy-brew.sh 를 두고, 문서의 경로 표기도 바로잡았습니다.

스크립트는 문서의 "릴리즈 절차" 6단계를 그대로 실행합니다.

VERSION 주입 → universal2 빌드(arm64+x86_64) → tarball(ad-hoc 서명)
→ sha256 → gh release create → 로컬 Formula/fcapture.rb 갱신
플래그동작
(없음)VERSION 파일 버전으로 릴리즈
--version 1.0.19버전 갱신(VERSION 파일 기록) 후 릴리즈
--dry-run빌드·tarball·sha256 까지만 — gh release·Formula 미변경

안전장치를 두 개 넣었습니다. 이미 존재하는 릴리즈 태그면 덮어쓰기 사고를 막으려 중단하고, --dry-run 은 Formula 갱신도 생략합니다 — 로컬 재빌드 tarball 의 sha256 은 실제 릴리즈 에셋과 다를 수 있어, 그 해시로 Formula 를 덮으면 기존 릴리즈(v1.0.18)와 불일치하기 때문입니다.

초안은 --dry-run 에서도 Formula 를 갱신하도록 짰다가, dry-run 이 기존 릴리즈의 확정 sha256(4fbba5c9…)을 로컬 재빌드 해시로 덮어쓴다는 걸 알아채고 갱신을 실 릴리즈 경로 안으로 옮겼습니다. dry-run 실행 후 git diff Formula/fcapture.rb 가 0 라인임을 확인했습니다.

--dry-run 전체 파이프라인을 돌려 universal2 바이너리가 x86_64·arm64 2아키텍처로 나오고 sha256 이 산출되는 것까지 확인했습니다. 실제 gh release·tap push 는 버전 변동이 없어 실행하지 않았습니다. tap repo(Finfra/homebrew-tap) push 는 로컬 clone 의존을 없애려 수동 안내 단계로 남겼습니다.
